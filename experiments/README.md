# 实验档案

每次调参跑完，用一条命令把这次运行压成一份档案：

```bash
python tools/记录实验.py <日志> -c moling/config.ron --标签 降初温 --假设 "初温从 31 降到 12 能否让最优真的下降"
```

产出本目录下两个文件：`<日期>-<时间>-<标签>.md` 与同名 `.png`（收敛曲线）。

## 为什么要有这个

一次 200 万步跑 1 分 41 秒，4000 万步要半小时。跑完屏幕上只剩一句「综合得分 6.5899」，
过两天就想不起**这个 6.59 是初始解还是优化出来的**、当时改了什么、试过哪些方向。
散落在 `runs/` 里的日志又只有数字没有意图。

所以一次实验一份文件，档案里既有机器能提取的（参数、得分、曲线），也有只能人写的
（假设、结论）。后两栏留空是故意的——跑之前先把「想验证什么」写下来，跑完再补
「结论」，否则容易变成「跑完看看结果，觉得还行，记不清为什么这么改」。

## 约定

- **假设**：跑之前写。一句话，写成可证伪的（「初温降到 12 后最优得分能低于 6.5」，
  而不是「试试降初温」）。
- **结论**：跑完写。有效 / 无效 / 意外发现，以及下一步试什么。
- **曲线 PNG 入库**：档案要能独立看懂，图不能只留在本机。单张约 110 KB，
  嫌仓库变大就定期把同批实验合并成一份汇总。

## 相关

| 工具 | 用途 |
|---|---|
| `code_genie plot` | 单独出图：`plot <日志> -o x.png --含当前`（PNG 需要 `--features chart`） |
| `tools/画收敛曲线.py` | 零依赖出 SVG，适合快速看 / 塞 Markdown |
| `tools/记录实验.py` | 本目录的生成器：参数 + 得分 + 图，一次写全 |

出 PNG 的二进制要单独构建：

```bash
cargo build --release --features chart
```
